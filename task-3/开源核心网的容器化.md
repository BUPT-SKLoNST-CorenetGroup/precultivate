# 开源核心网的容器化

## 1. 任务概述

通过上次任务，我们对核心网有了一个初步的了解。在上次的核心网了解中，我们会注意到，5G的核心网引入了SBA架构(如果在学习过程中没有调研到这一点，建议改变一下学习的方式，调研时不仅需要知道怎么使用，更需要知道为什么要这样做。)，引入了SBA之后，核心网的网元，可以像我们在互联网领域常见的网站一样进行部署，例如微服务化，容器化等。

本次任务我们将学习使用容器化的方式来部署核心网，了解容器的基本原理，给核心网带来的好处等。

本次任务需要使用到的工具有：

1. docker、podman等容器工具。

## 2. 任务描述

本次任务的核心是体会"手动管理容器"和"用编排工具管理容器"之间的差别，从而理解 docker-compose 这类工具存在的意义。请在实验报告中对比这两种方式的工作量与易错点。

1. 安装docker，参考[https://docs.docker.com/engine/install/](https://docs.docker.com/engine/install/)

> 也可以使用podman，如果你使用Fedora作为你的Linux distro,podman 是默认安装的，不过如果你对linux不熟悉，建议还是从ubuntu入手。等对Linux有了一定了解，Fedora会是一个更舒服的选择。

2. 参考[https://free5gc.org/guide/0-compose/](https://free5gc.org/guide/0-compose/)，使用docker-compose部署核心网。不要满足于"跑起来"，请逐条阅读 compose 文件，理解 docker-compose 每一步在干什么：它定义了哪些容器？容器之间的网络是怎么连起来的？数据卷、依赖顺序、特权配置又是为什么这样写的？

3. 自己手写 dockerfile 来构建核心网镜像，使用 docker 手动管理启动容器，配置容器网络，让这些手动启动的网元能够互相通信、并最终把核心网跑通。完成后对比第 2 步，感受为什么需要引入 docker-compose。

> 本次任务比较有难度，建议可以从什么是docker了解一下，可以参考一下[https://zhuanlan.zhihu.com/p/187505981](https://zhuanlan.zhihu.com/p/187505981)

> 提示：UPF 这类网元往往需要额外的网络权限或内核能力（例如操作 gtp5g、修改路由），手动起容器时这部分最容易踩坑，正好可以借此理解 compose 文件里那些特殊配置在做什么。

## 3. 需要掌握的知识

> 标有 `*` 的为通识/重点知识点，需要能够不假思索地解释清楚；其余知识点了解其基本内容、并知道如何查询即可。每个知识点后附有自测问题，你可以尝试回答这些问题来检测自己是否真正掌握。

1. ***docker的基本使用**

   自测问题：
   - 镜像（image）和容器（container）是什么关系？同一个镜像能不能跑多个容器？
   - Dockerfile 里 FROM、RUN、COPY、CMD、ENTRYPOINT 各自的作用是什么？CMD 和 ENTRYPOINT 有什么区别？
   - 容器和虚拟机的本质区别是什么？容器靠内核的哪些机制（namespace、cgroup）实现隔离与资源限制？

2. **容器化核心网的部署**

   自测问题：
   - docker-compose 替你自动做了哪些"手动起容器时很繁琐"的事情（网络、依赖顺序、批量启停）？
   - 多个网元容器之间是如何互相发现和通信的？自定义 bridge 网络和默认网络有什么不同？
   - 为什么 UPF 容器通常需要 `NET_ADMIN`、`privileged` 或挂载特定设备？去掉这些配置会发生什么？
