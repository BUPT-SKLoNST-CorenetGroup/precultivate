# 计算机网络的基础知识

## 1. 任务概述

通过本次任务，我们将会从计算机的基础协议栈学起。掌握Linux网络的配置方式和基本的计算机网络协议栈。

本次任务需要使用到的工具有：

1. virtualbox，vmware，wsl2等等虚拟机软件，也可以安装linux+windows双系统，如果你并不熟悉linux安装，建议先从虚拟机开始上手，总之需要用一个linux的初始环境。
2. netplan、networking、ifupdown、netmanager等等网络配置工具，这取决于你linux的发行版，这些工具通常会直接安装在linux发行版上，你只需要会使用其中一个就可以。
3. wireshark、tcpdump等网络抓包工具,二选一即可,建议如果你不是特别熟悉,可以先从wireshark开始
4. nc

> 在使用这些工具之前,我建议可以先可以结合AI来了解一下这些工具是干什么的,你也可以选择其他类似功能的东西,例如你想使用qemu来做虚拟机管理

## 2. 任务描述

本次任务希望你动手把"一个数据包从本机发出、又收到回应"的全过程亲眼看一遍，并能讲清楚每一步在协议栈里发生了什么。最终交付一份实验报告，包含你的配置过程、抓包截图以及对报文的逐层分析。

1. 打开你的linux终端,配置你的linux主机可以链接到互联网。完成后，你应当能说清楚自己这台主机的 IP 地址、网关、DNS 是什么，以及它们分别是怎么来的。

> 对于带有桌面环境的系统,你也可以使用可视化操作来实现;链接到互联网,可以使用wifi(802.11)或者有线网络;如果你使用vbox或者vmware,你会发现默认配置已经链接.

2. 启动抓包软件,监听你的网卡。

> 如果你不是很熟悉,你可以先了解一下linux下的网卡是怎样的,感受一下一切皆文件的思想,了解一下监听的概念

3. 在终端发起 `ping baidu.com` ,查看抓包软件抓到的包并进行分析。在报告中说明：你抓到了哪些协议的报文？它们出现的先后顺序是怎样的？这个顺序为什么是这样？

> 如果你比较熟悉,可以分析整个协议栈的过程,包括DNS解析,ARP等等协议,如果不是很熟悉,推荐先查看IP层的相关知识,并分析该ICMP报文.

4. 创建两台虚拟机A，B，保证两者可以ping通。在A上使用`nc -l -p 9999`,在B上使用`nc ${A_IP} 9999`，并抓包分析TCP链接建立的过程。在报告中标出三次握手对应的报文，并解释每个报文里的关键字段。

> 这里抓包需要分析TCP非常著名的三次握手，理解TCP的报文格式。注意是理解，不是背诵。

> 创建两台虚拟机是一个很重的操作，这里"重"可以好好理解一下，可以使用轻量级的方式代替，例如使用namespace和veth对。

> 虚拟机之间可以ping通是一个十分复杂的配置，深入底层需要去了解一下虚拟机的网络配置，可以查询相关知识，了解VBox或者VMware等虚拟机管理软件实现的虚拟网络架构，有多种架构，需要选择一种来实现我们的需求，(VBox应该是NAT，仅Host，内部网络，NAT网络四种，如果我没记错的话)

## 3. 需要掌握的知识

> 标有 `*` 的为通识/重点知识点，需要能够不假思索地解释清楚；其余知识点了解其基本内容、并知道如何查询即可。每个知识点后附有自测问题，你可以尝试回答这些问题来检测自己是否真正掌握。

1. **linux命令行的基本操作**（在上述实验中，会使用很多linux的命令）

   自测问题：
   - 你用什么命令查看本机的网卡和 IP 地址？输出里的 `inet`、`mtu`、`UP`、`LOWER_UP` 分别是什么含义？
   - 如何查看本机的路由表和默认网关？数据包是依据什么决定从哪张网卡发出去的？
   - "一切皆文件"在网络上如何体现？你能在 `/sys` 或 `/proc` 下找到网卡相关的信息吗？

2. **掌握抓包**（抓包是我们最常见、最常用、最好用的分析网络故障的方式）

   自测问题：
   - 抓包工具是如何拿到本不属于本进程的网络报文的？（提示：混杂模式、内核 BPF）
   - 如果只想看 ICMP，或只想看某个 IP、某个端口的 TCP 报文，你会怎么写过滤条件？
   - 抓包看到的"包"对应协议栈的哪一层？你能从一个帧里依次剥出以太网头、IP 头、TCP/ICMP 头吗？

3. ***掌握TCP和IP报文的基本格式**

   自测问题：
   - IP 头部里 源/目的地址、TTL、协议号（protocol）这几个字段分别起什么作用？TTL 为什么会递减？
   - TCP 头部里的 序列号（seq）、确认号（ack）、标志位（SYN/ACK/FIN/RST）、窗口（window）分别表示什么？
   - 同样是把数据从 A 送到 B，TCP 和 UDP 在报文结构和可靠性上有什么本质区别？

4. ***掌握TCP握手的流程**

   自测问题：
   - 三次握手的每一步，SYN/ACK 标志位和 seq/ack 的值是如何变化的？
   - 为什么是"三次"握手，两次为什么不够？四次行不行？
   - 握手过程中连接两端会经历哪些状态（如 SYN_SENT、SYN_RCVD、ESTABLISHED）？连接关闭时的"四次挥手"又是怎样的？
