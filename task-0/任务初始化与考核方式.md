# 任务初始化和考核方式

## 1. 概述

task-0是后续task的准备工作。培训任务会依托于github进行，因此，git是一个必须要掌握的工具。通过本次任务，来学习如何从github搜索需要的代码，以及如何将代码push到github上。

## 2. 任务描述

之后所有的培训任务将会通过github来发布，因此，第一个任务是熟悉git与github的完整工作流，并跑通一次"获取任务 → 完成 → 提交"的闭环。

1. 注册一个github账户，并完善基本信息。

> 建议给仓库 BUPT-SKLoNST-CorenetGroup/precultivate 一个 star，方便后续找到它。

2. 查询仓库 `BUPT-SKLoNST-CorenetGroup/precultivate`，后续任务都会在该仓库发布。把它 clone 到你的本地环境，浏览仓库目录结构，理解任务是如何组织的。

3. 配置好向 github 推送代码所需的身份认证。

> github 早已不支持用账号密码直接 push，你需要在 HTTPS + Personal Access Token 或 SSH key 两种方式中选择一种并配置好。建议顺便理解一下这两种认证方式的区别。

4. 完成你选择的 task，并撰写一份实验报告，记录你的思路、操作、遇到的问题和结论。

5. 提交你的成果，方式如下：

   1. 创建一个属于你自己的 github 仓库，并将其设置为 public；
   2. 将任务完成的报告和代码，通过 `add` → `commit` → `push` 推送到该仓库；
   3. 在 `BUPT-SKLoNST-CorenetGroup/precultivate` 提交一个任务完成的 issue，在 issue 中附带你自己的仓库地址。

> 你可以一个任务一个仓库，也可以所有任务共用一个仓库，仓库中目录的组织形式也完全由你来自主决定。实验报告的格式和文件形式也不设限制，可以使用PDF，也可以word，当然还是建议尝试一下markdown。

## 3. 需要掌握的知识

> 标有 `*` 的为通识/重点知识点，需要能够不假思索地解释清楚；其余知识点了解其基本内容、并知道如何查询即可。每个知识点后附有自测问题，你可以尝试回答这些问题来检测自己是否真正掌握。

1. **git的基本命令** init、add、commit、push 的用法

   自测问题：
   - git 的工作区（working directory）、暂存区（staging area）、本地仓库、远程仓库分别是什么？一次代码改动从被你写下到出现在 github 上，依次经过了哪些区域？
   - `git add` 和 `git commit` 的区别是什么？只 commit 不 push，你的代码在哪里？
   - `git status`、`git log`、`git diff` 分别能帮你看到什么？

2. **github的基本使用方式**

   自测问题：
   - 如何把一个本地仓库和 github 上的远程仓库关联起来（remote）？
   - push 时 github 如何确认"你就是你"？HTTPS+Token 和 SSH key 两种认证方式各是怎么工作的？
   - clone、fork、issue 分别是用来做什么的？什么场景下用 fork 而不是 clone？
